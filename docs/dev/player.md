# The Player and the Sample Project

> **Status: v0.1.** `sparxel-player` opens a project folder and plays it in a window, or
> headless for automated runs. `samples/hello` is a small village to try it with, in both
> render styles; CI plays it on every change.
>
> Code: [`player/main.cpp`](../../player/main.cpp). Sample:
> [`samples/hello`](../../samples/hello), generated by
> [`tools/make_sample.py`](../../tools/make_sample.py). Tests:
> [`tests/player/run_sample.cmake`](../../tests/player/run_sample.cmake) and the sample
> test in [`tests/game/runtime_test.cpp`](../../tests/game/runtime_test.cpp).

## 1. Playing a project

```sh
sparxel-player samples/hello            # in a window
sparxel-player samples/hello --headless --frames 120 --no-audio --screenshot frame.png
```

| Option | Effect |
|---|---|
| *(folder)* | The project to play. Without one: the `game` folder beside the executable, or the executable's own folder, if either holds a project file (an exported game, [export.md](export.md)); otherwise the folder the player is started in |
| `--headless` | Draws without a window, so it needs no display, at 60 frames a second of game time as fast as the computer can; runs always play the same |
| `--frames N` | Stops after N frames |
| `--no-audio` | Plays without sound |
| `--screenshot file.png` | Saves the last frame drawn as a PNG |

- In a window, the game runs in real time; closing the window ends it. The window shows
  the game's internal resolution at the largest whole-number scale that fits
  ([rendering.md](rendering.md) §4), and its title is the game's name.
- **What it prints:** every line logic writes with Log blocks and every message
  characters say (as `said: …`, [ui.md](ui.md) §3), on standard output, and
  every problem (a project issue, a sound that cannot play, a save that fails) on
  standard error, so creators see them while testing.
- Exit codes: 0 after playing, 1 if the game cannot start (the reasons are printed), 2 for
  unknown options.

### Testing from the editor

**Play** in the editor starts the player with `--debug` (exported games never have it):

- **F1** opens the **debug menu**, over the paused game, with a magenta border so it is
  plainly not part of it (`DebugMenu`, `plan/02` N4): **Give items** (every row of
  `data/items`, what is carried, and gold; Right or Interact gives one, or 100 gold, Left
  takes one), **Story flags** (each flag set so far, on or off: Interact switches it),
  **Quests** (each with how it stands: Interact completes it), **Go to…** (everything
  named, by name: Interact puts the player just below it and closes the menu), **Heal the
  party**, and **Close**. Up and Down choose; Cancel goes back. F1 again closes it.
- **Time controls** (`plan/02` N3): **F2** pauses the game and goes on again, **F6**
  moves a paused game on by one step (a sixtieth of a second), and **F7** plays it at half
  speed, to look at a jump or a battle closely. A magenta line in the bottom-left corner
  says which is on. The debug menu still works while paused.
- **Live editing**: once a second the game reads again what changed in `assets/` while it
  plays (`Runtime::reload_changed()`, `plan/02` N2): pictures and sprite sheets (saved in
  Sprite Studio, or imported from Aseprite) show at once, and data tables and translations
  are read again. Logic and scenes still need the game started again.
- **F3** shows how long frames take, in plain language (`plan/02` N5): frames a second,
  milliseconds of logic and of drawing, how much of a 60-a-second frame that is (*plenty
  of room*, *close to the limit*, or, in red, *too slow, it will stutter*), and how many
  entities there are.

## 2. The sample: Hello Sparxel

A 20 × 12 tile village in a stone wall, with a path, a hero to walk with the arrow keys or
a gamepad, an elder to talk to with Z, and a gate on the east road, which leads to a
second scene: the road, where a stream is heard louder the closer the hero comes, and
whose west end leads back. It uses most of what the engine does today:

| Part | What it shows |
|---|---|
| `art/hero.png` | A 3 × 4 character sheet: three walking frames for each of four directions (Walk Animation) |
| `art/tiles.png` | Grass, path and wall tiles: the ground map, and a solid wall map one tile high, so in the Diorama style the wall stands as blocks |
| `art/elder.png` | An elder who is a Solid Body and an Interactable |
| `sfx/chime.wav` | Played when the player talks to the elder |
| `logic/main.drules` | Rules for the start (a welcome message on screen), talking (the elder's words in a message box, and a question whose answer changes the reply; counting talks in a variable) and the gate (a Trigger Area, with a message); and a Brain, `weather`, turning sunny and rainy, and dimming the `lighting` when it rains |
| `sfx/stream.wav` | A second of running water that repeats without a click: the road's stream, a Sound Source |
| `maps/road.dscene` | The road: its own hero, a milestone to arrive at, the way back (a Trigger Area) and the stream |
| `logic/road.drules` | *Go to scene …, arriving at …* through the gate and back (arriving by the village's lantern), and *When a scene starts* saying where the hero is now |
| `maps/village.dscene` | The village, with two warm Lights for the Diorama style (a lantern by the gate, a lamp by the elder) that glow when the rain dims the day |

Switch `"render_style"` in `project.sparxel.json` to `"diorama"` to see the same village
in 3D. Its `look` adds a little bloom, warmth and a vignette, and in the Diorama style a
tilt-shift band that keeps the middle of the screen sharp.

- **All of it is made by `tools/make_sample.py`:** the pixel art, the chime and the stream are drawn
  and synthesised in code, so the sample has no third-party assets and regenerates
  exactly. Its `.meta` files have fixed GUIDs, so playing it never writes into the
  repository.

## 3. Tests

| Test | Checks |
|---|---|
| `player_classic_2d`, `player_diorama` | CTest plays a copy of the sample headless for 120 frames in each style: it must start, report no problems, and print the welcome message (`said: Welcome to the village`) and the Brain's first line |
| `player_long_run` | 2,000 frames in the Diorama style, past the rain at 30 seconds (it must print *It starts to rain.*). Headless runs once grew in memory every frame and crashed after about 900 frames ([rendering.md](rendering.md) §4) |
| The sample in the Diorama style | Renders the village in 3D and checks that no path pixel appears alone in the grass. That once happened: in perspective, a texture coordinate on a tile's edge rounded into the next tile of the atlas. World quads now keep their coordinates a hundredth of a texel inside the tile ([rendering.md](rendering.md) §7); the test fails without that |
| The sample through the gate | In the game's runtime with recorded input (in the editor's model tests): the hero walks east, closing messages, into the gate; the scene becomes the road with the hero exactly at the milestone and the village's elder gone; the stream's Sound Source starts there, silent while the screen is black, and is heard once the scene has faded in; no problems and no script errors |
